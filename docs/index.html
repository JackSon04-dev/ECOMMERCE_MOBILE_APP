🚀 Deployment & Infrastructure

AWS EC2 · Docker Compose · Nginx SSL · Let's Encrypt · 6 Containers
1
Mobile App Build (APK) & Keystore
Tạo Keystore (Khóa bí mật): Trước khi build ứng dụng Flutter, phải tạo một Keystore để làm khóa bí mật. Khóa này đảm bảo tính xác thực cho app và bắt buộc phải lưu trữ cẩn thận để có quyền phát hành các bản cập nhật (updates) của app sau này.
Build APK Release: Cấu hình file build để liên kết với Keystore, sau đó chạy lệnh build xuất ra file cài đặt .apk tối ưu dung lượng để cài đặt trực tiếp trên thiết bị Android.
2
AWS EC2, Docker & HTTPS SSL
Thiết lập AWS EC2 & Domain: Khởi tạo Instance EC2 trên AWS tại khu vực Singapore (ap-southeast-1). Lấy IPv4 Public của VPS dán vào DNS Namecheap cho domain clothesstores.app và SSH vào VPS để Git Clone source code.
Cấu hình SSL (Let's Encrypt): SSH lại vào VPS, tải một số công cụ để cấu hình HTTPS và trích xuất chứng chỉ SSL. Nhận được 2 key quan trọng để liên kết vào Nginx:
ssl_certificate /etc/letsencrypt/live/clothesstores.app/fullchain.pem;ssl_certificate_key /etc/letsencrypt/live/clothesstores.app/privkey.pem;
Docker Compose (6 Containers): Hệ thống được chia làm 6 containers (Redis, RabbitMQ, Backend API, Background Worker, Cron Job, Admin Web). Khi chạy ở môi trường Local, hệ thống chỉ chạy HTTP ở Port 80. Khi deploy lên VPS, Nginx được mount volume chứa SSL và mở ra Port 443 (HTTPS) an toàn.
Cấu hình Nginx (Force HTTPS): File nginx.conf cấu hình lắng nghe cả port 80 (HTTP) và 443 (HTTPS). Nếu user truy cập qua cổng 80, Nginx lập tức bắt buộc chuyển hướng qua 443 (return 301 https://$host$request_uri;) để đảm bảo security. Mọi request tới /api được proxy_pass đẩy ngầm xuống container backend nội bộ cùng header X-Real-IP.
3
MongoDB Atlas Cloud Database
Triển khai MongoDB Atlas (Low Latency): Khởi tạo Cluster cơ sở dữ liệu trên MongoDB Atlas. Điểm mấu chốt là chọn cùng Region Singapore với máy chủ AWS EC2. Tư duy thiết kế Global này giúp khoảng cách vật lý giữa API và Database gần như bằng 0, tối ưu hóa triệt để độ trễ mạng khi các service giao tiếp nội bộ.

⚙️ Backend Module Overview

Node.js · Express.js · MVC · 11 Services · 8 Schemas
1
Layered Architecture
Microservices RESTful API MVC Pattern
2
Security
Authentication & Authorization: JWT Access Token, Refresh Token, Google OAuth, Role-Based Access Control.
Validation: Tích hợp Joi Validation ở tầng HTTP request và payload từ client trước khi xử lí — tránh request rác.
Centralized Error Handler: Hệ thống xử lý lỗi tập trung tự phân loại lỗi, trả JSON chuẩn format. Kết hợp asyncHandler loại bỏ toàn bộ try-catch lặp lại trong mọi controller.
3
Improving Performance
Response Compression: Toàn bộ phản hồi nén Gzip. Giảm kích thước từ 23KB → 1.5KB với 20 object sản phẩm/request.
Redis Caching: Lưu đệm dữ liệu thường xuyên (danh sách sản phẩm, bộ lọc). Giảm thời gian phản hồi từ 130ms → 60ms khi cache hit.
MongoDB Indexing: Tạo Indexes cho các trường hay truy vấn để tăng hiệu năng.
Full-text Search & Autocomplete: Atlas Search Index với logic AND + Autocomplete Index riêng cho gợi ý real-time khi gõ.
Keyset Pagination: Cursor-based dùng lastId thay skip/limit. Hiệu năng ổn định khi dữ liệu lớn.
4
Scalability & High Availability
Message Queue (RabbitMQ): Đẩy tác vụ nặng vào queue — Worker xử lý riêng, giải phóng main server. Hạn chế mất dữ liệu khi server dừng đột ngột.
ACID Transaction - Atomic-Guarantee + Retry: Logic đặt/hủy hàng bọc trong MongoDB Transaction với withRetry tự động retry khi WriteConflict. Tránh oversell, tự động rollback.
Rate Limiter Redis: Giới hạn request cho API thông thường và API nhạy cảm (Login, Register). Redis caching tối ưu đọc dữ liệu.
Cron Job: Mỗi 15 phút quét đơn hàng PayOS chưa thanh toán sau 30 phút → đẩy lệnh hủy vào RabbitMQ.
Cache Stampede Prevention: Cơ chế khóa tạm đảm bảo duy nhất 1 request truy vấn DB khi cache hết hạn — tránh hàng trăm request đồng thời đánh DB.
TTL Auto-Cleanup: Thông báo tự xóa sau 30 ngày bằng MongoDB TTL Index expireAfterSeconds — không cần cron dọn dẹp.
5
Additional Features
AI Chatbot (Gemini API): Phân tích câu hỏi tự nhiên thành bộ filter MongoDB. Kết quả cache theo filter — nhiều user hỏi giống nhau share 1 cache.
PayOS VietQR: Tạo QR code thanh toán + xác thực webhook HMAC. Return URL không update DB (bảo mật), chỉ Webhook đã verify mới cập nhật.
Firebase Push Notification: FCM tokens request lên GCP, tùy chỉnh hình ảnh, nội dung, âm thanh. Broadcast chia chunk 400 token → RabbitMQ xử lý async.
Cart Stock Validation: Giỏ hàng tự kiểm tra tồn kho thật mỗi lần mở, tự điều chỉnh số lượng hoặc xóa sản phẩm đã gỡ.
Cloudinary Auto-Resize: Upload ảnh sản phẩm tự resize 500×500, ảnh review 800×800 — giảm bandwidth cho mobile.
Google Login OAuth: Xác thực Google Auth token từ client gửi lên bằng google-auth-library. Tự động cấp cặp JWT Access/Refresh Token nội bộ và quản lý phiên đăng nhập thống nhất.

📱 Mobile App UI Overview

Flutter · Dart · Riverpod · 12 Services · 7 Models · 20+ Screens
1
Product & Business Layer
Mục tiêu sản phẩm: Ứng dụng thương mại điện tử chuyên biệt ngành hàng thời trang, cung cấp trải nghiệm mua sắm mượt mà từ khâu tìm kiếm đến thanh toán.
Tính năng cốt lõi: Duyệt sản phẩm với biến thể (Màu sắc/Kích cỡ), quản lý giỏ hàng tự động đồng bộ, theo dõi trạng thái đơn hàng thời gian thực.
Điểm chạm thông minh: Tích hợp AI Chatbot (Gemini) hỗ trợ tư vấn sản phẩm, thanh toán không chạm (QR Code/Webview) và hệ thống thông báo đẩy (FCM) để giữ chân khách hàng.
2
Architecture & State Management
Kiến trúc MVC (Model-View-Controller): Ứng dụng tổ chức mã nguồn theo mô hình MVC. Model (thư mục models) xử lý cấu trúc dữ liệu, View (screens/widgets) đảm nhận UI, và Controller (providers/services) làm trung gian xử lý nghiệp vụ và quản lý trạng thái.
State Management (Riverpod): Dùng flutter_riverpod làm nòng cốt để quản lý state phức tạp, tính đồng bộ cao (Giỏ hàng, Đơn hàng, Xác thực), tách biệt hoàn toàn Business Logic khỏi UI.
Smart Routing & Interceptors: Quản lý hơn 20 màn hình qua Named Route Generator. Kết hợp class AuthGuard tự động chặn các thao tác cần quyền (mua hàng, đánh giá), bung popup Đăng nhập và tự động thực thi lại thao tác đang dang dở sau khi đăng nhập thành công.
3
User Interface & User Experience
Tính nhất quán (Consistency): Bọc các màn hình bằng CustomAppBar và BottomNavBar đóng gói sẵn, chặn triệt để lỗi giật/xô lệch layout (layout shift) khi chuyển Tab.
Hệ thống Reusable Widgets: Đóng gói các UI độc lập như ProductCardWidget, ChatbotWidget, và các Bottom Sheet tùy chỉnh (AddToCartBottomSheet, SizeGuideSheet).
Trải nghiệm Tìm kiếm (Search UI): Tính năng Autocomplete gọi API qua cơ chế Debounce 300ms, kết hợp hiển thị lịch sử tìm kiếm tối ưu hóa luồng gõ phím.
4
API & Network Integration
Auto-Refresh Token & Race Condition Lock: Tự động bắt lỗi HTTP 401. Dùng Completer<bool> để khóa (lock) tiến trình Refresh Token — đảm bảo dù có 10 request cùng lỗi 401, API cấp lại token cũng chỉ gọi 1 lần duy nhất.
Cổng thanh toán & Background Polling: Tích hợp VNPay, ZaloPay (qua Webview) và PayOS VietQR (vẽ mã QR bằng qr_flutter). Xây dựng luồng Polling API quét trạng thái đơn hàng mỗi 5 giây, kết hợp WidgetsBindingObserver để tự động kiểm tra ngay khi user chuyển từ App ngân hàng trở về App.
Centralized API Service: Quy tụ toàn bộ method GET/POST/PUT/DELETE vào ApiService xử lý Header Authorization và JSON Deserialization tự động.
5
Local Storage & Security
Bảo mật Token: Mã hóa accessToken và refreshToken thông qua flutter_secure_storage.
Lưu trữ bộ đệm (Caching): Tận dụng shared_preferences lưu dữ liệu ít nhạy cảm như Search History và dữ liệu giỏ hàng chưa đồng bộ.
Bảo mật Xác thực: Tích hợp Google Sign-In, kết nối luồng cấp phát JWT an toàn phía Backend.
6
Performance Optimization
Optimistic Update & Debounce Sync (Cart): Giỏ hàng tách làm 2 lớp: UI và API. Tăng/giảm số lượng lập tức hiển thị trên UI. Đợi 5 giây không thao tác mới gộp (batching) các thay đổi gửi lên MongoDB, giảm 80% lưu lượng API dư thừa.
Lazy Loading (Infinite Scrolling): Quản lý list dài mượt mà bằng ScrollPaginationMixin. Tự động gọi API tải thêm dữ liệu khi user cuộn chạm ngưỡng 90% màn hình.
Client-Side Stock Validation: Tải kèm biến thể (Variants) ngay trong Object Product. Bắt lỗi hết hàng ngay trên UI thiết bị thay vì chờ Server trả về lỗi.
Quản lý Hàng đợi Thông báo: Lưu trữ Firebase Message vào pending queue khi app ở trạng thái bị tắt hoàn toàn (Terminated state), nhấn vào tự điều hướng tới thông báo đó hoặc vào chi tiết đơn hàng tùy loại thông báo.

💻 Admin Dashboard UI Overview

Vue 3 · Vite · Axios · Composition API · 14 Views · Lazy Loading
1
Product & Business Layer
Mục tiêu sản phẩm: Hệ thống quản trị (CMS) chuyên dụng cho chủ cửa hàng, cho phép kiểm soát toàn diện luồng vận hành của ứng dụng E-commerce.
Tính năng cốt lõi: Quản lý CRUD Sản phẩm đa biến thể (Màu/Size), xử lý đơn hàng, quản lý mã giảm giá, và kiểm duyệt đánh giá từ người dùng.
Điểm chạm thông minh: Bảng điều khiển (Dashboard) trực quan hiển thị doanh thu theo thời gian thực (MongoDB Aggregation). Cập nhật trạng thái đơn hàng 1-click tự động đẩy thông báo FCM tới app khách hàng qua RabbitMQ.
2
Architecture & State Management
Kiến trúc Component-Based: Sử dụng Vue 3 với Composition API để tổ chức code module hóa, phân tách rõ ràng giữa Logic, Template và Style.
State Management (Reactivity): Sử dụng ref và reactive tích hợp sẵn của Vue 3 để quản lý trạng thái local cho các biểu mẫu (Forms) và danh sách dữ liệu động.
3
User Interface & User Experience
Tính nhất quán (Consistency): Layout quản trị tiêu chuẩn với Sidebar Navigation và Topbar, duy trì bộ khung vững chắc qua hệ thống Vue Router View.
Vanilla CSS: Sử dụng CSS thuần với hệ thống CSS Variables chung (như var(--blue), var(--red)...) giúp tối ưu hóa kích thước thay vì lạm dụng thư viện UI cồng kềnh.
Hệ thống Reusable Components: Đóng gói các thành phần UI dùng chung như Bảng dữ liệu (Data Table), Biểu mẫu Modal, Nút xác nhận để dễ bảo trì.
4
API & Network Integration
Auto-Refresh Token (Axios Interceptors): Tự động bắt lỗi HTTP 401, gọi ngầm API /auth/refresh, cấp lại Token và tự động replay request lỗi gốc.
Failed Queue Pattern: Xử lý Race Condition hiệu quả. Khi 1 request đang refresh, các request 401 đến sau sẽ được đẩy vào failedQueue. Sau khi lấy token mới, resolve hàng loạt.
Xử lý dữ liệu đa nền: Giao tiếp qua giao thức FormData cho các API Upload nhiều ảnh sản phẩm lên Cloudinary.
5
Local Storage & Security
Quản lý Phiên (Session): Lưu trữ an toàn accessToken vào Local Storage để duy trì trạng thái đăng nhập trên trình duyệt.
Route Guards (Điều hướng an toàn): Bắt sự kiện router.beforeEach, chặn mọi truy cập chưa xác thực vào Dashboard và tự động điều hướng về màn hình Login.
Force Logout Cascade: Nếu Refresh Token cũng hết hạn (hoặc user bị ban), hệ thống tự dọn dẹp LocalStorage và ép đăng xuất hoàn toàn (Force Logout) ngay lập tức.
6
Performance Optimization
Vite Bundler: Sử dụng bộ công cụ Vite siêu tốc để HMR cực nhanh khi dev và tối ưu hóa dung lượng bundle tĩnh khi Build Production.
Lazy Loading Routes: Áp dụng kỹ thuật code-splitting thông qua hàm import() ở cấp độ Router. Trình duyệt chỉ tải JS của màn hình quản lý nào đang được xem.
Tối ưu hóa Băng thông (Images): Thay vì tải ảnh lớn gốc, Admin nhận các thumbnail từ Cloudinary đã được resize sẵn (width/height), làm giảm hàng chục lần lưu lượng mạng.
